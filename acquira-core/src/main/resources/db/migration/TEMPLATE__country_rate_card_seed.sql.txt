-- PURPOSE
-- -------
-- After V2026_07_31_02 the interchange engine is COUNTRY-LEVEL: onboarding a new
-- country (Oman / Bahrain / Egypt / ...) is pure DATA — seed rate rows keyed by
-- country_code with tenant_id = NULL (country default). No code/schema change.
--
-- HOW TO USE
-- ----------
-- 1. Copy this file to a real, versioned migration name, e.g.
-- 	  V2026_08_XX_01__rate_card_oman.sql
-- 2. Replace the two placeholders throughout:
-- 	  {{COUNTRY_CODE}}   ISO-3166 alpha-2, must exist in ref_country. OM / BH / EG.
-- 	  {{CAP_CCY}}        ISO-4217 currency the caps below are denominated in
-- 	                     (OMR for OM, BHD for BH, EGP for EG). Percentages are
-- 	                     currency-agnostic; only cap_amount / *_ticket bounds are
-- 	                     in this currency. NOTE OMR & BHD are 3-decimal (1000
-- 	                     minor units) — see ref_country.decimal_notation_value.
-- 3. Fill the VALUES rows with the country's REAL interchange / scheme rates.
--    The rows below are the UAE ('AE') card, left ONLY as a structural example —
--    DELETE or overwrite every rate before shipping. Do NOT ship AE numbers for
--    another country.
-- 4. Add the new file to spring.sql.init.schema-locations in BOTH
--    application.properties and application-prod.properties (at the end).
-- 5. Set each tenant in this country: UPDATE tenant SET home_country_code =
--    '{{COUNTRY_CODE}}' WHERE ... ;  (defaults to 'AE').
-- 6. BACKFILL: fees compute at INGEST, so existing rows keep their old fee until
--    re-ingested. Re-upload / re-pull the affected months for this country's
--    tenants to recompute interchange + scheme fee off the new card.
--
-- IDEMPOTENCY / SPLITTER RULES (keep them):
--   * NO $$ dollar-quoting anywhere (Spring ScriptUtils splits on ';').
--   * interchange_rate_local match columns are nullable, so ON CONFLICT can't
--     make the seed idempotent — guard with NOT EXISTS (country has zero rows).
--   * scheme_fee_rate / mcc_sector_map keys are keyed via unique indexes that
--     COALESCE tenant_id/scheme_group — a NOT EXISTS guard is used here too so
--     the file is safe on whichever unique key the table currently carries.
-- ============================================================================
